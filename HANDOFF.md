## Рабочая схема (роли)

- **Opus (основной агент) — архитектор + ревьюер.** Продумывает план/фазы/детали, после написания кода делает ревью, тесты, шлифовку.
- **Sonnet — кодер.** Пишет код по готовому плану. Суб-агент `coder` определён в `.claude/agents/coder.md`.
  - Делегирование: `Agent` tool, `subagent_type: "coder"`.
  - ⚠️ Кастомные агенты подхватываются при старте сессии. Если в свежей сессии `coder` не виден в списке — используй `subagent_type: "general-purpose"` с `model: "sonnet"` и вставь роль кодера из `.claude/agents/coder.md` в начало промпта.
- **Архитектурные решения кодеру НЕ делегируются** — их принимает Opus.

## Что сделано (Этапы 1–3)

### Этап 1 — скелет + заметки
- `bot/config.py` — конфиг через `pydantic-settings` (все поля из `.env`).
- `bot/main.py` — старт, разводка `BOT_MODE=polling|webhook`, `init_db()` в обоих режимах.
- `bot/middlewares/access.py` — фильтр «только один пользователь» (через `data["event_from_user"]`).
- `bot/handlers/notes.py` — `/note` → `knowledge/inbox/YYYY-MM-DD.md`, `/start`.
- `Dockerfile`, `docker-compose.yml`, `.env.example`, `.gitignore`, `requirements.txt`.
- `knowledge/` — дерево доменов + шаблоны `_templates/`.

### Этап 2 — RAG-ядро
- `rag/embedder.py` — ленивый синглтон e5, префиксы `passage:`/`query:`, нормализация.
- `rag/indexer.py` — frontmatter → токен-чанкинг (токенайзером модели) → ChromaDB; инкрементально по `file_hash` в метаданных чанков.
- `rag/retriever.py` — `search()` → топ-K чанков с источниками.
- `bot/tools/llm.py` — OpenRouter через `openai.AsyncOpenAI`, system prompt из CLAUDE.md.
- `bot/handlers/ask.py` — `/ask` + свободный текст (ответ простым текстом, без parse_mode).
- `bot/handlers/admin.py` — `/reindex`.
- Хук в `notes.py`: `/note` индексируется сразу после сохранения.

### Этап 3 — задачи и дашборд
- `db/schema.sql` — таблицы `tasks`, `notes_index` (с `IF NOT EXISTS`).
- `db/database.py` — async CRUD на `aiosqlite`: `init_db`, `add_task`, `get_today_tasks`, `get_week_tasks`, `complete_task`.
- `bot/handlers/tasks.py` — `/task` (с парсингом даты через `dateparser` и тегом `#домен`), `/today`, `/week`.

Порядок роутеров в `main.py`: `notes → admin → tasks → ask` (ask последним из-за catch-all на свободный текст).

## Смоук-тест после первого запуска (порядок)

Запусти на VPS (`BOT_MODE=polling`), затем в Telegram:

1. `/start` — должен ответить списком команд.
2. `/note тестовая заметка` — ответ «Сохранено…», файл появился в `knowledge/inbox/`.
3. `/reindex` — **первый раз медленно** (грузится модель e5 ~1 ГБ), затем сводка по файлам/чанкам.
4. `/ask что я записывал?` — ответ Claude с блоком «Источники». (нужен OpenRouter-ключ с балансом)
5. `/task позвонить подрядчику завтра` — «Задача добавлена #N», срок = завтра.
6. `/today` и `/week` — задача отображается.

Если что-то падает — смотри `docker compose logs -f bot`.

## Архитектурные решения (дублирую — их не было в коде явно)

- **ChromaDB встроенная** (`PersistentClient`), без отдельного сервиса.
- **Embeddings: `intfloat/multilingual-e5-base`** (контекст 512). Считаем сами через sentence-transformers, НЕ встроенной функцией Chroma — ради контроля e5-префиксов (`passage:` при индексации, `query:` при поиске), `normalize_embeddings=True`, коллекция `brain` с cosine.
- **Чанкинг — токенайзером модели** (скользящее окно `chunk_size`/`overlap` из настроек).
- **Инкрементальный реиндекс**: `file_hash` (md5) хранится в **метаданных чанков Chroma**, НЕ в SQLite. Таблица `notes_index` (SQLite) зарезервирована под `/stats` (Этап 4).
- **LLM: `anthropic/claude-sonnet-4-5` через OpenRouter** (в `.env`, меняется одной строкой).
- **`BOT_MODE=polling|webhook`** — polling для старта/одного пользователя, webhook для прода (нужен домен + TLS reverse-proxy).
- **Ответы LLM — простым текстом** (без parse_mode), чтобы сырой вывод не ломал парсинг сущностей Telegram.
- **Доступ** — middleware по `TELEGRAM_ALLOWED_USER_ID` (бот только для одного пользователя).

## Известные ограничения / на что смотреть

- **Первый `/ask` или `/reindex` медленный** — скачивание модели e5 (~1 ГБ). Можно предзагрузить модель в `Dockerfile`, чтобы убрать задержку рантайма (не сделано).
- **Тяжёлый Docker-образ** — `sentence-transformers` тянет `torch` (несколько ГБ).
- **`dateparser` хуже распознаёт сокращения** дней («пт») — лучше «в пятницу». Может ошибочно принять число в тексте за дату.
- **`notes_index` (SQLite) пока не используется** — заполняется/читается в Этапе 4 для `/stats`.
- **`complete_task()` в `db/database.py` готов, но без хендлера** — под inline-кнопки ✅ в Этапе 4.
- Сообщения Telegram ограничены 4096 символами — очень длинные ответы LLM не разбиваются на части (не критично, но учесть для Этапа 4).
